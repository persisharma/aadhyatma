# Actual-component review harness

Run `node mobile/visual/remaining-content/build.mjs` from the repository root after installing mobile dependencies and running `npm ci --prefix mobile/visual/remaining-content` for its pinned web dependencies. Serve the resulting `dist` folder. Example: `/?kind=stuti&id=hanuman-bahuk&page=43&lang=hi&size=L&width=320`.

The harness imports production Stuti, Suktam, Ashtakam, Kavacham and Vishnu readers, Katha Library, Saptashati collection, and weekday/canonical-link components. It accepts `kind`, the matching content `id`, zero-based `page`, `lang` (hi/en/gu/kn), `size` (M/L), and `width`. Native navigation, persistence, audio and sharing are adapters; this is not evidence that those services work on a device. `capture.cjs` covers first/last/longest pages of all eight new payloads, extended Vishnu core pages and the four discovery components in hi/en/gu/kn (M at390px, L at320px). It saves viewport/bottom images, text, metrics and errors. The dedicated GitHub Actions workflow retains evidence even on a capture-step failure. Native services remain adapters.

Native iOS/Android, long Bahuk layout, accessibility, font-scale, share/export, offline behavior and performance remain pending. Keep the PR draft until these checks and visual review are complete.

Generated dist/captures are intentionally excluded from git. These sources reproduce the preview; they are not a replacement for actual built screenshots.
