# /ship Learnings — plan phase

Learnings are auto-captured after each /ship run. Read before starting the phase.

### Verify repo is actually clean before claiming `create-expo-app .` will work at repo root

**Seen:** 1x — 2026-04-22
**Category:** plan-assumption
**Example:** Plan v1 claimed cuzco/ only had README+.git; in reality it had .claude/, .context/, .ship-* state files, and create-expo-app itself emits AGENTS.md/CLAUDE.md/.claude/settings.json by default. Scaffold collision was guaranteed.
**Resolution pattern:** Before planning a root scaffold, `ls -la` the target dir AND consult the tool's default-output manifest. Default to a subdirectory (mobile/, web/, etc.) for any non-trivial generator.

### Pin Expo SDK only after checking Expo Go store compatibility window

**Seen:** 1x — 2026-04-22
**Category:** sdk-lifecycle
**Example:** Plan v1 pinned SDK 55 to match reference app; on 2026-04-22 Expo Go App/Play Store builds were still on SDK 54 during the transition. Would have forced a dev-build setup before the first device run on a hello page. Fix: pin SDK 54, treat 54→55 migration as a separate ticket.
**Resolution pattern:** Before pinning an Expo SDK, check docs.expo.dev/sdk for the Expo Go transition state. If stores lag, pin the Go-compatible SDK unless dev-build is already in scope.

### ThemeContext is a structural contract, not a leaf concern — introduce useTheme() hook on day one

**Seen:** 1x — 2026-04-22
**Category:** architecture
**Example:** Plan v1 deferred ThemeProvider as "easy to port later". Reference app shows module-level `colors` frozen by `StyleSheet.create()` forces a deferred-require dance and a bundle reload on theme switch. Any screen doing `import { colors }` would need refactoring when ThemeProvider lands. Fix: `useTheme()` from the first commit, static light palette behind a context provider.
**Resolution pattern:** If screens will ever consume theme, expose theme via hook/context from commit one — never direct module import of mutable tokens.

### Blank-typescript template does not ship Expo Router — own index.ts explicitly

**Seen:** 1x — 2026-04-22
**Category:** template-assumption
**Example:** Plan v1 said "leave index.ts as generated by create-expo-app (it registers App via Router)". Wrong — blank-typescript ships no Router. Only default/tabs templates do. Fix: explicitly create index.ts with registerRootComponent(App) and set package.json "main": "index.ts" (matches CreditScore's mobile/index.js).
**Resolution pattern:** When choosing a create-expo-app template, check its README for entry wiring. blank* → own your own entry. default/tabs → Router is wired for you.
