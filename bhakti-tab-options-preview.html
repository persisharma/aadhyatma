What's already settled

These hold whichever option you pick — they're the rest of the handover, and the repo turned out to be further along than §1 suggested.

The shared screen already exists. PanchangScreen ships a पंचांग | व्रत-पर्व | ज्योतिष segment today, with the date state already lifted above all three and an initialTab route param. So §3 is mostly wiring two more tabs into a container that's already built — not building it.

The one genuinely new mechanism is the sync rule: the bottom highlight has to follow the segment. That needs a custom tab bar reading a section context, because three tabs must resolve to one mounted screen rather than three.

  • ▸Bottom bar becomes होम · भक्ति · पंचांग · व्रत · ज्योतिष. व्रत takes a moon, ज्योतिष a star — never a second swastika beside पंचांग.
  • ▸अन्य leaves the bar for the header icon on every tab. Its whole stack stays mounted and reachable — only the tab button goes.
  • ▸The mini-player already docks above the nav app-wide, from App.tsx. Nothing to build.
  • ▸entry_point ships as a local analytics seam — typed, unit-tested on all four sources, one sink to swap later.
  • ▸Vrat reminders keep opening the specific observance; the screen underneath just mounts on व्रत, so back lands there.
