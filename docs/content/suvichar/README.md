# Suvichar: personalized devotional sharing

Daily Bhakti now opens a separate card section with Ready-made cards selected first and Create your own alongside it. Choose a deity and frame, add an optional name or family name, choose a starter reflection or ready-made wish, edit the message, save a complete favorite and share the native PNG through the OS sheet, including WhatsApp. Changing art or selecting another thought preserves the sender. Artwork subscriptions survive typing; only the measured text/card child resets.

The card follows Option 2: complete artwork above readable text, a separate optional “सप्रेम — name” line, and clear native Vedansh branding with vedansh.app/get. Source art has no baked-in message, name or logo. Long messages grow the lower paper section; they are never truncated or automatically shrunk. Exports are 1080 pixels wide with their full measured height.

## Artwork

42 full-resolution WebP masters were generated with the built-in image-generation tool, using the three user-approved frame references. Full prompts, dimensions, authoring PNG hashes and exact delivered SHA-256 hashes are recorded in [sources.json](../../../mobile/assets/suvichar/sources.json). Combined delivery size is 24095482 bytes. All 42 files were fully decoded and visually inspected in five contact sheets on 22 October 2026. Native preview/export review remains pending.

The composition review checked text-free paper, complete figures, deity-specific attributes and distinct shrine forms: Ram Darbar has Ram, Sita, Lakshman and Hanuman; Salasar has the vermilion bearded/moustached shrine face; Khatu Shyam is the crowned sheesh presentation; Tirupati is the dark-stone Venkateswara murti with namam and four arms. These are original illustrations, not claims of photographic temple darshan. Reviewed hero fractions are .60 for the straight frames, .64 for floral scenes and .62 for Tirupati’s temple frame.

## Text directory and occasions

The app ships an original opening reflection, 20 further authored daily reflections, and seven explicit wish choices: morning, Diwali, Holi, Ram Navami, Janmashtami, Mahashivratri and Navratri. It also supports a reader’s own message. None is presented as a scripture quotation. UI copy is authored in Hindi, English, Gujarati and Kannada; authored content uses the app’s existing contentByLang policy. Personal names/messages remain verbatim.

[editorial-directory.json](editorial-directory.json) contains the requested 1,000 original Hindi text drafts and artwork briefs. It is outside the shipped content graph and retains editorial-review-pending status. [occasion-directory.json](occasion-directory.json) records the broader festival/occasion plan. Festival selection in this implementation is explicit; automatic Panchang date recommendations and scheduled notifications are not implemented. There are 42 reusable master images, not 1,000 rendered cards.

## Publication blocker

The runtime manifest is intentionally empty. Image sharing stays disabled until the new paintings have been published and verified; text, preferences and navigation still work. The attempted publication failed because R2_ACCOUNT_ID, R2_ACCESS_KEY_ID and R2_SECRET_ACCESS_KEY are not available in this workspace. No unpublished hashes have been activated.

With authorized R2 credentials in the environment, run from the repository root:

```sh
node scripts/prepare-suvichar.mjs --publish
node scripts/prepare-suvichar.mjs --verify
```

An existing authenticated Wrangler setup can use `--publish --wrangler`. The script uploads all 42 source objects, verifies their public CDN bytes and only then atomically writes mobile/src/data/suvicharManifest.json. Commit that generated manifest after successful verification. Source paintings must never be imported or required into the bundled app asset graph.
