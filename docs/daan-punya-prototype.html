शिक्षा पहले · खाता बीच में · दान-द्वार सबसे अंत में

Five interactive scenarios of the giving layer. The organizing rule everywhere: the feature opens on महत्व — why the tradition gives, in the shastra's own words — and the donate hand-off is the terminal act of a journey, never a button on the home, never a tab, never the pitch. Click through the phones: shastra cards, the journey stepper, vaar chips, the ledger form (गुप्त toggle live), and the Phase-2 hand-off interstitial all work.

It is not verified content and must not be transcribed into the app. Real rows ship only after the PRD-26 verification gates (§6.2, §10) are cleared; directory rows additionally need the store-policy review (§6.1).

What this screen is — and is not

  • Opens on महत्व: today's occasion line (panchang-computed — मकर संक्रान्ति here), the vaar line, and the four-layer source spine (Veda → Upaniṣad → Gītā → Itihāsa). PRD-26 §2.7 / §4a.
  • Zero give affordances. No donate button, no directory door, no amount anywhere. The §9 surface-contract test pins this: the home renders no external-linking affordance.
  • The Gita card is the only layer already bundled — it deep-links into the shipped reader (gita/chapter-17.json). Katha cards open the shipped katha library entries.
  • Vaar chips drive the same 7-row table PRD-21 needs (data/daan/vaar.ts, shared module).
  • The single quiet door at the end goes to the खाता (ledger) — recording what one already gives is the primary behaviour.

Register

  • Copy explains the reason ("til because…"), never commands and never scores. Copy-guard test rejects fear/guilt/points vocabulary in data/daan/.

Why a stepper, not a page

  • The §2.7 contract requires the hand-off to be unreachable until the educate steps have rendered — "not skippable in one scroll-tap". A stepper makes the contract structural, not stylistic.
  • Steps: 1 महत्व (why this day) → 2 शास्त्र (the verse) → 3 कथा (shipped-story link) → 4 क्या दें (items + reasons) → 5 संकल्प-भाव + terminal actions.
  • On step 5, "खाते में दर्ज करें" leads; "दान-द्वार" trails it, visibly tagged बाहरी / external, and exists only in Phase 2 builds.
  • संकल्प-भाव is static bilingual copy in Phase 1; when PRD-20 lands it becomes composeSankalp(…, karma:'daan') with the user's real tithi-coordinates.
  • Entry doors into this journey: Observance Detail (daan days), Home Today strip line, vaar row, Pitru Smaran, vidhi daan steps — every door enters at step 1.
A user who leaves at any step has been fully served — understanding is the product. The journey never nags toward its last step.

Ledger contract

  • Self-attested, device-only. AsyncStorage @vedansh/daan-ledger:v1 — the routine done-marks / japam-counter pattern. No cloud, no account.
  • Tithi-stamped by the engine. Every entry carries the panchang tithi + occasion rule id automatically — the ledger reads like a samvat, not a bank statement.
  • गुप्त दान is first-class: flip the toggle — amount/detail fields vanish (not just hidden-on-render: never captured). The entry lists as "गुप्त दान · तिथि" only.
  • Only date + category are required — the U6 gate-and-hundi case is the primary path. Under 10 seconds.
  • No totals, no streaks, no charts of generosity. Export (share sheet, PRD-06 pattern) is the only aggregation, and it leaves the app only by the user's hand.
  • Form uses house specs: TextField variant="form" 48dp, chip idiom from muhurat-disha.

The hand-off posture (PRD-26 §5 P2 / §6)

  • No directory tab exists. This screen is reachable only from a journey's terminal step — never in one tap from anywhere.
  • The screen itself is educate-first: work → verification → related practice → then the action row. "खाते में दर्ज करें" (record) is placed before "दान करें".
  • The give button carries the बाहरी/external tag; the interstitial states plainly that the app is outside the transaction. Return-flow record offer fires at most once, declining is silent.
  • Registration ids + verification date are shown to the user — §6.2's two-source + govt-registry gate, re-verified on cadence; stale rows drop to draft.
  • Phase 2 rides a store release for review visibility (§6.1); degrades to information-only rows if review objects — Phase 1 educate/ledger is never hostage.

Every door, every entry at step 1 of the journey

  • Observance Detail (daan-significant days: संक्रान्ति, अक्षय तृतीया, अमावस्या family, एकादशी family, पितृ पक्ष) — quiet last-section door, shown in frame.
  • Home Today strip — a daan line only on daan-significant days, same door.
  • Katha library — daan-themed kathas gain a "इस कथा का दान" footer cross-link; the journey's कथा step links back. Two-way, no duplication.
  • Vidhi conduct — Karwa Chauth karwa-dana step (+ future daan step kind, PRD-22) gets a record affordance on the step card; conduct stays swipe-only.
  • Pitru Smaran — shraddha-tithi detail links anna-daan educate + record; ancestor context stays private (PRD-17 stance), never on any share surface.
  • Daily Routine — "add वार-दान to routine" creates the weekly unit (e.g. शनिवार तिल-तेल); marking it done offers the one-tap ledger entry.
  • Kundali / PRD-21 — graha-daan rows reuse vaar.ts; the daśā-aware line deep-links here.
  • Theerth (Phase 2) — temple detail gains a giving line only where the trust has a verified directory row.
  • PRD-20 सङ्कल्प — journey step 5 upgrades to composeSankalp(karma:'daan') when it ships.
Ordering rule everywhere: the daan door is the last section of its host screen, and reminders (opt-in, existing vrat/festive families) name the occasion and the tradition — never an amount, never a recipient.
