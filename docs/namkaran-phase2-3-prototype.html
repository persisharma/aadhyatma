A · Result screen — the Phase-2/3 additions in place

Renders only when the nakshatra's presiding devata resolves in the curated NAKSHATRA_DEITY_LINKS map → deities.ts (v1: Shravana → Vishnu; Ardra → Shiva pending reviewer sign-off). D · Home — DISCOVER Spotlight (Phase 2b)
1One FeatureSpotlight, existing rules. Registered in HomeScreen's spotlights array; all cards render, order shuffled once per app open (shuffleBySeed) — no pinning, no weighting. Standard NEW badge; Devanagari glyph tile (no emoji). Opens the Namkaran entry screen via panchangTabTarget — never a saved result.
Privacy rule (hard): the card is static copy only — it never reads Namkaran storage, so it can never surface a saved birth detail, computed syllable, shortlist count, or even a "resume" hint. A source guard test pins that the Home module imports nothing from data/namkaran/. The launcher grid stays 16 tiles — no 17th tile.

E · Lock screen — the one-shot naming-day reminder
1Generic by rule, not by choice of words. Title is the fixed word नामकरण; the body is fixed copy baked at schedule time in the reading language (hi/en authored; gu/kn transliterated). Never on the lock screen: the child's name, any shortlisted name, the syllable/nakshatra/pada/rashi, birth date or time, the printed ceremony date, or the fact that details are remembered. Payload allow-list is { type, dateKey } — schema-tested.
Budget & lifecycle: prefix namkaran-reminder, cap = 1 pending slot against the shared iOS 64-slot pool (audited in the same PR). Fires 07:00 local on the chosen day only — no advance notice, no recurrence. Cancelled/re-planned when the saved result is deleted, the date changes, or the day passes (prune on load + foreground). Tap deep-links to the saved result; a missing record falls back to the Namkaran entry screen.

F · Naming-day Home presence — a chip, not a tile
1Today-strip chip (Pitru Smaran private-chip precedent): muted-gold ॥ नामकरण · आज का दिन, rendered only while the reminder record exists and its dateKey is today. Decision: generic on-device copy only — Home is glanceable by anyone, so it follows the same never-list as the lock screen (no name, no syllable, no birth data). Tap opens the saved result. Derived from the one reminder record — no new storage, no panchang solve, no widget or share exposure.
2Self-cleaning: past dateKey prunes on load/foreground; chip and pending notification disappear together. The launcher grid is untouched — the parent PRD's "Home tile alongside a grid re-flow" is fulfilled by this chip; no grid re-flow is scheduled.
Content gates carried, not re-scoped: the three open Phase-1 gates — namakshar convention sign-off (§11.1), the attested shipping name corpus (§11.2), and the independent Android Maestro run (§11.9) — block any store release of every Namkaran surface, including everything on this page. The नामकरण संस्कार vidhi carries its own PRD-19-style gate: two-source verification in an egress-capable environment, DRAFT until sign-off, illustrative copy above never transcribed. Privacy: newborn birth details remain the app's most sensitive data; no surface on this page — notification, Spotlight, chip, vidhi checklist — may carry a name, syllable, or birth field. Both phases are pure JS + bundled JSON → OTA-capable (no audio). No external assets besides Google Fonts.
