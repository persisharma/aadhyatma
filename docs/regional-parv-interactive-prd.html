Where it fits — four touched surfaces, everything else inherits

The lens is a presentation filter at the read path (resolveObservancesForYear). Every surface downstream — day panel, month grid tags, आगामी, Vrat & Parv catalog, Home Today strip, ask engine — inherits the filtered list with zero code change. Only four surfaces change, all in the Panchang tab; the three frames below are them.

F · A श्रेणी tile — क्षेत्रीय पर्व joins the browse grid. NEW: a sixth tile after पूजा विधि, count subtitle doubling as state (1 सक्रिय · 11 कैलेंडर). Cons: a category is the wrong noun — व्रत, पर्व, कथा are content types you browse; a lens is a preference you set. Decision (signed off 2026-09-06): E, with the seed line as the bridge. The क्षेत्र ledger row on व्रत-पर्व is the durable home (it is exactly the shape of मेरा व्रत, which users already understand), and the one dismissible seed line on the पंचांग day view — where the new dates actually appear — deep-links to the same sheet for the first-encounter moment. Pattern A's header chip is dropped: the real row is full. W2-10 is now "the ledger row + the seed line"; the chip/badge item is gone from the build inventory.

What needs no change at all

Day panel · month grid पर्व/व्रत tags · आगामी · Vrat & Parv catalog counts · Observance List · Home Today strip · ask-engine date intents — all read resolveObservancesForYear and inherit the filter. Search is lens-blind by principle: searchObservances always searches the whole catalog, so nothing is ever unfindable because a checkbox is off.

How seeding works, without asking

On first Panchang entry after the update, after interactions settle: bundled city → its new stateCode → lens; pincode city → the pincode table's state (already lazily loaded); Ujjain-the-default → no seed. One dismissible line announces it. Travelling never changes the calendar; jain only ever comes from a deliberate tap.

Why W2 ships as a no-op

The mechanism lands with zero lensed rules — verified only by the two existing visibility:'regional' orphans (karthigai-vrat, rohini-vrat) converting. The filter, seeding, memo keys, widget and notification gates all get verified against a calendar nobody's household depends on yet — before any content rides it.

Guardrails, risks & what we deliberately won't do

① No identity question, ever

Not at onboarding, not in settings, not as a "personalise" card. The lens is seeded from the city the user already chose and is a plain list of calendars. The seed copy names the city, never the person (R6 — "seeding feels like profiling" — is answered by copy + dismissibility + no modal).

② A lens only ever ADDS

It never hides a universal observance. A Jain household still sees Janmashtami — subtraction is a religion question wearing a filter's clothes. Recorded as Open decision 2 because it will be re-proposed.

③ Presentation only, instant, offline

The precomputed table carries every rule; the filter runs at read with the lens set in the memo key. Toggling re-runs no scan (the "Panchang froze" incident is why live scans on render paths are banned).

④ No shipped date moves

Every wave's PR diffs the regenerated table by rule id: only new ids, no existing date moved. The one tithi-affecting change (pradosh for बछ बारस) is its own separately-verified PR, never a content rider.

⑤ No new notification family

Nothing joins the default-on festive catalog. A lensed observance reaches reminders the way every observance does: ★ follow (page ④).

⑥ Both lineages, both named

Śvetāmbara Paryushana and Digambara Das Lakshan; Vat Savitri (Amavasya) and Vat Purnima. Never one as "the" date. Where published sources genuinely conflict, the observance goes to Appendix B — sources or silence.

Metrics (bundle-only, no analytics)

  • Coverage, printed at build: days/year with ≥1 observance per lens. Targets — Rajasthan 40+, Bihar/Mithila 30+, Jain 25+, each state lens 15+.
  • Universal-day load: the ±0 counter-metric above.
  • The ask engine's unanswered log: a festival users keep asking for by name is the next wave's input.

Non-goals

  • No Sikh Gurpurabs, no Islamic/Christian/Parsi/Buddhist calendars — different reckonings, not lenses over this engine.
  • No multi-language UI; regional names ride search terms.
  • No per-observance toggles, no "hide this festival".
  • No travel-triggered calendar changes; the seed is one-time.
  • No mela ticketing/timings/darshan content.
