How the tour drives navigation

  • Overlay, not modal — FeatureTour.tsx uses a translucent Modal (transparent + overFullScreen) so the real screen reads through behind the dim layer.
  • Live nav — Each step has a navigateTo route (HomeTab/Home, MoreTab/Wishlist, MoreTab/Reminders, DailyBhaktiTab). The tour calls navigationRef.dispatch(CommonActions.navigate(...)) on every step change, so when the user taps Next they actually land on the surface the copy is describing.
  • Anchor + pointer — Each step chooses top / center / bottom placement plus an optional ▲ / ▼ pointer triangle that nudges the eye toward the relevant region without spotlight measurement (robust across screen sizes).
  • Touches blocked — While the overlay is up, only its own buttons receive taps. Stray taps on the real tabs/cards are caught by the modal, so the tour stays linear.
  • Persistence — TourContext writes tour-completed-v on Done/Skip and whats-new-seen-v on first install so a brand-new user is never double-prompted.
  • Replay — More → Show Tour Again calls resetTour() and re-opens the overlay from step 1.
