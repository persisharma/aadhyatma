How the tour drives navigation

  • Overlay, not modal — FeatureTour.tsx uses a translucent Modal (transparent + overFullScreen) so the real screen reads through behind the dim layer.
  • Live nav — Each step has a navigateTo route. The tour calls navigationRef.dispatch(CommonActions.navigate(...)) on every step change: HomeTab/Home, PanchangTab, HomeTab/RoutineToday, AudioTab, DailyBhaktiTab, MoreTab/Wishlist, MoreTab/Reminders. The user actually lands on each surface.
  • Anchor + pointer — Each step picks top / center / bottom plus ▲ / ▼ pointer to nudge the eye without spotlight measurement (robust across screen sizes).
  • Touches blocked — Modal catches taps on the underlying UI so the tour stays linear; only Back / Next / Skip advance it.
  • Persistence — TourContext writes tour-completed-v on Done/Skip and whats-new-seen-v on first install so a brand-new user is never double-prompted.
  • Replay — More → Show Tour Again calls resetTour() and re-opens from step 1.
  • Post-update — Bump APP_TOUR_VERSION in data/tour/whatsNew.ts when you ship a release; add a new keyed entry listing only its new features. The What's New sheet fires once, on the first launch after the update.
